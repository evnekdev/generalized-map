# Topology contract and verification

Inspected 2026-11-10: `evnekdev/generalized-map`, default branch `master`, baseline
`da5da931033dc1a28be46618dfc1b003cd306725`. Owning issue:
[generalized-map#1](https://github.com/evnekdev/generalized-map/issues/1).
The regression tests and corrections accompanying this document are on
`codex/verify-cell-topology`. Findings below concern the stated fixtures, not
every constructor or arbitrary higher-dimensional topology.

## Alpha slots and dimensions

The import is `generalized_map::NGMap` (Cargo package `generalized-map`).

| Parameter | Actual representation |
| --- | --- |
| `N` | Number of stored alpha slots per dart; storage indices `0..N`. |
| `ndims` passed to `new` | Number of active alpha slots; active alpha/cell indices `0..ndims`. Callers must ensure `ndims <= N`; `new` does not check this. |
| `NA` | Capacity of attribute containers/slots, associated with chosen cell dimensions; independent of `N`. |
| `NL` | Capacity of user-defined weak links per dart; these are outside alpha topology and do not affect cell/component orbits. |

For a conventional 2-dimensional map, use three active slots (alpha0, alpha1,
alpha2), e.g. `NGMap::<3>::new(3)` or `NGMap::<4>::new(3)`. A path/cycle using
only alpha0 and alpha1 uses two active slots. Neither `N` nor `ndims` is the
highest alpha index or a geometric embedding dimension. Active slots also
do not prove that a component is a regular cell of the highest available
dimension: even an isolated dart belongs to a cell orbit at each active index.

`number_alpha_nonfree()` returns **`ndims`**, including entirely free active
slots, despite its historical name. It is the existing public way to obtain
the active slot count. `number_alpha_nonfree_component()` instead scans all
`N` slots and counts non-self links: when `ndims < N`, its count includes null
inactive slots. Do not use that statistic as topological dimension or as
snapshot validation. This behavior is source-observed and unchanged here.

For a live dart and an active index, alpha-free means `get_alpha(&d, i) == d`;
`is_free` is true and `get_alpha_if_exists` returns `None`. Inactive slots
`ndims..N` contain null dart index 0, **not** a self link. They are not additional
mathematical involutions on the live dart set. Index 0 is reserved and excluded
by `iter_all`; it must not be supplied as a live seed. Raw indices are not
validated handles: callers must use live dart IDs and active dimensions.

### Why `get_seq(i, N)` works for the verified cases

`src/iterators.rs` builds cell sequences over capacity `N`, while
`src/orbits.rs::get_seq` excludes index `i`. `IteratorOrbit` premarks null
index 0, so extra inactive links cannot enter an orbit or join components.
On the public constructors tested here, this gives exactly the active-alpha
cell partition for active `i < ndims`.

Executed: a square at `(N, ndims) = (3,3)` and `(4,3)`, two sewn squares at
`(3,3)` and `(5,3)`, and a path at `(2,2)` and `(4,2)`. Increasing a ring from
two to three active slots initializes alpha2 to self; decreasing clears it to
0. The lower-dimensional partitions remain unchanged. **No iterator defect
was reproduced from using `N`; the orbit implementation is retained.**

Capacity-only cell indices `ndims <= i < N` can currently return component-like
orbits, but those are outside the active-cell contract. With two active slots,
a ring is a closed 1-dimensional cycle; choose three active slots to interpret
it as one face. No API infers the intended geometric filling from a ring.

## Mathematical and traversal contracts

For the finite set `D` of live darts and active indices:

- Each alpha maps `D` to `D` and satisfies `alpha_i(alpha_i(d)) = d`.
- Fixed points represent free connections and are allowed. In particular,
  `create_dart` produces a dart free in every active alpha; this is not a
  violation of the involution axioms.
- For `j >= i + 2`, `(alpha_i alpha_j)^2(d) = d`, equivalently the two
  involutions commute. No such composition condition is imposed on consecutive
  indices. The 2-dimensional tests exercise the nontrivial pair `(0,2)`.
- The `i`-cell of `d` is the orbit generated by all active alphas except
  alpha-i. These orbits are equivalence classes and partition `D` for each `i`.
- A component is the orbit under all active alphas. Free connections do not
  create another component or an exterior cell.

These axioms also appear in the independent
[CGAL public mathematical definitions](https://doc.cgal.org/latest/Generalized_map/index.html).
That manual was consulted only as a definition reference; no CGAL source,
numbering, class design or runtime dependency is used.

`iter_darts_in_cell` enumerates flags, and `iter_dart_per_cell` selects one
representative per cell. `darts_in_same_cell` tests membership.
`iter_incident(d, i, j)` means **target dimension `i`, source dimension `j`**;
`i != j`. It yields one representative per distinct target cell intersecting
the source orbit. It does not count repeated incidences or order a boundary.

`iter_adjacent(d, i)` crosses alpha-i from flags of the source i-cell and
deduplicates the resulting i-cells. The correction accompanying this
document skips free alpha links. A nonfree crossing into the source cell's
own orbit is retained as genuine self-incidence, as in the one-edge loop. This is
alpha-i adjacency, not a promise to enumerate every i-cell sharing any
lower-dimensional cell: a consumer needing that relation can compose incident
traversals. Traversal order and representative choice are not identity contracts.

Sewing imposes additional operational preconditions: distinct seed darts,
alpha-i freedom and isomorphic orbits under indices nonconsecutive to `i`.
These are conditions of this operation, not additional generalized-map axioms.
`sew` returns false when its predicate fails. Alpha2 sewing of the square
fixtures pairs both endpoints of the shared edge, preserving alpha0/alpha2
commutation, merging the shared edge/endpoint cell identities while keeping
the two face orbits distinct.

## Exact fixture results

All inputs are small hand-derived combinatorial fixtures, use no geometry,
randomness or external data, and require exact equality (no numerical tolerance).
Construction uses public `create_dart`, `create_edge`, `create_chain`,
`create_ring`, `sew`, and `change_dim`; there is no private-storage access.

| Fixture | Active slots | Darts | Vertices | Edges | Faces | Components |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Single edge | 2 | 2 | 2 | 1 | outside active dimension | 1 |
| Square | 3 | 8 | 4 | 4 | 1 | 1 |
| Two squares sewn along one edge | 3 | 16 | 6 | 7 | 2 | 1 |
| Three-edge path | 2 | 6 | 4 | 3 | outside active dimension | 1 |
| Four-edge cycle | 2 | 8 | 4 | 4 | outside active dimension | 1 |
| Two separate squares | 3 | 16 | 8 | 8 | 2 | 2 |
| One-edge loop | 2 | 2 | 1 | 1 | outside active dimension | 1 |
| Square with opposite edge occurrences sewn to each other | 3 | 8 | 2 | 3 | 1 | 1 |

- Edge: alpha0 exchanges the two darts; alpha1 is free. Each vertex orbit
  contains one dart and the edge orbit contains both. Both endpoints are incident.
- Square: vertex and edge orbits have two darts each; the face has eight.
  Each edge has two endpoint vertices; the face has four distinct edges. All
  eight darts are alpha2-free, giving four boundary edges.
- Sewn squares: the shared edge has four darts and two incident face cells;
  six external edges remain distinct, with one incident face each. Alpha2
  crosses the shared boundary; alpha0/alpha2 commute. Both choices of endpoint
  correspondence in the sewing operation pass.
- Loop: one incident vertex is returned, but the distinct darts `d` and
  `alpha0(d)` retain the two endpoint occurrences at that same vertex.
- Folded square: one face has four edge occurrences but only three distinct
  incident edge cells. The alpha walk retains both occurrences of the sewn
  edge. This verifies recoverable multiplicity, not admissibility as a regular
  cellular face for a future adapter.

The tests compare all active cell partitions, orbit membership, incident
sets, and alpha-i adjacency to a separate reachability oracle over public
alpha reads. They also check reordered generators, a fixed permutation of
square dart allocation labels, reversed local boundary direction, and concurrent
iterator lifetimes with non-LIFO drop. No IDs or iteration ordering are assumed
except explicit fixture correspondences.

## Information available to an external cell-complex adapter

| Requirement | Existing public information and consumer responsibility |
| --- | --- |
| Enumerate 0/1/2-cells | `iter_dart_per_cell(i)` and `iter_darts_in_cell(d,i)` with at least three active slots for faces. |
| Identify cells in a fixed topology | A representative dart plus dimension, or a canonical member of its orbit; construct opaque snapshot IDs externally. `DartIndex` is copyable/hashable, not a persistent cell ID. |
| Find incidence | `iter_incident` gives distinct cells; orbit intersections give their flag membership. |
| Preserve multiplicity | Retain ordered flag occurrences through alpha reads. Distinct-cell incidence/adjacency iterators intentionally lose multiplicity. |
| Recover local orientation/order | For the tested closed polygon face, choose a seed endpoint dart `d`, cross the edge with alpha0, then advance with alpha1: `next(d) = alpha1(alpha0(d))`. This visits four oriented edge occurrences on a square. Starting at `alpha0(d)` reverses order and endpoints. |
| Classify boundary/interior | For the verified 2D fixtures, alpha2-free edges are unsewn boundary edges; nonfree alpha2 traverses the interior shared edge. No exterior face is allocated. |
| Disconnected complexes | `iter_dart_per_component` and `iter_darts_in_component`, or alpha reachability. |
| Immutable validated snapshot | Borrow `&NGMap`, enumerate live IDs and active alphas, validate axioms/admissibility, and copy the required cell/flag information into consumer-owned storage. No upstream validation object is required. |

Along the shared edge the second face can start at
`alpha0(alpha2(d))`: its selected directed edge runs between the same endpoint
cells in the opposite direction. This gives the combinatorial information for
the consumer's signs. Generalized-map stores no preferred cell orientation,
signed coefficients, chain operators, weights, or global manifold orientation.
Tests verify direction/order information only; no signed boundary or chain
complex is implemented here. Global orientability and the choice of an
individual cell basis orientation are separate questions.

**No additional public API is necessary for a finite validated 0/1/2-dimensional
snapshot of the verified structures.** `next`, `prev` and `opposite` on `NGMap`
remain unfinished and are unnecessary: use alpha reads. The adapter can be
implemented without adding upstream abstractions or duplicating sewing.

## Limits and compatibility

Recommendation for [cell-complex#3](https://github.com/evnekdev/cell-complex/issues/3):
**READY WITH LIMITATIONS**, using the traversal/sewing corrections accompanying
this document (pin the reviewed revision or wait for its merge).

- The adapter must check live IDs, active dimension, alpha closure/involutions,
  nonconsecutive compositions and its own allowed cell structures. Generalized-map
  has no public all-purpose `validate` method. Passing these finite tests is not
  a proof that every existing modification preserves all axioms.
- Restrict initial chain extraction to validated regular graph/polygonal
  structures. The loop/folded examples show available occurrence data; general
  nonregular attachments, arbitrary CW complexes, nonorientable identifications,
  higher-dimensional maps and full signed chain algebra remain unverified here.
- Alpha2 is an involution: three distinct face sheets sharing a single edge
  cannot be represented as a pure 2D edge orbit under alpha0/alpha2 with the
  usual polygon interpretation. Do not force that construction. A single
  2-cell with multiple disconnected boundary contours is likewise not one
  connected alpha0/alpha1 face orbit; a subdivided annulus is a different input.
- Alpha2-free identifies an unsewn surface boundary, including hole boundaries.
  Topology alone does not distinguish an outer contour from an inner hole,
  specify an ambient embedding, or add an exterior face. Annular/hole fixtures
  were not executed in this run.
- A lower-dimensional component inserted into a map with three active slots
  still has a formal 2-cell orbit. Do not treat all such orbits as filled disks;
  mixed-dimensional intended-cell selection needs an explicit adapter contract.
- Source-observed `unsew` mutates links and then reaches `todo!()`; `next`,
  `prev`, `opposite`, `restrict` and some constructors are also unfinished.
  No fixture requires these operations. Their completion and unrelated
  modification algorithms are outside this verification.
- No public signature or serialized storage layout changes. Corrected
  adjacency skips free alpha links while retaining nonfree self-incidence;
  sewing to an occupied target now returns
  false; independent live iterators no longer overwrite each other's marks.
  A local workspace source/manifest scan found one external dependency,
  `layeredtrees`, whose sources use `NGMap<0,...>` weak-link storage and do not
  call these topology operations. It was not built. In-crate `is_insertable`
  computes an adjacent-cell count but does not use it in active conditions.
  `cell-complex` remote `master` has no dependencies yet. This is a bounded
  consumer inspection, not an ecosystem-wide compatibility claim.
